# Architecture review corrections for lifecycle implementation

These corrections amend the root decisions and supersede the corresponding proposal sections. Independent review: exact Opus 5.5, `claude-mw3rk1vn-vrbq1diy`. No live permission changes.

1. Cancellation binds an explicit, hashed affected-occurrence preview, expected schedule version and the relevant pending/admitted dispatch versions. REMAINING uses `fromOccurrence`, never an overloaded `occurrence`. Repeats require finite `maxOccurrences` and capture the original exclusive window; a later environment extension cannot extend that series. Store `lastOccurrence`, `endRequestedOperationKey` and `endRequestedAt`. Reject a cancellation affecting an admitted/unknown mutation; do not retry automatically. Cancelling only future occurrences truncates the series without changing the bound generation of an unaffected current occurrence. Later steps of an admitted occurrence use that occurrence's fixed generation/admission, never silently adopt a new post generation. A skipped first occurrence may be followed by a later pending occurrence; predecessor PUBLISHED, RESOLVED_PUBLISHED or explicitly CANCELLED is sufficient. Define QUEUE/PUBLISHED row expectations accordingly.
2. Persist `nextActionAt`, `nextStep`, per-call `pollCount`, `nextPollAt`, `pollDeadlineAt`, `lastPolledAt` and the continuation envelope needed for read-only resumption. Renew the DB lease at each step; do not rely on an unrenewed35-minute lease. Expired admission with a DISPATCHING mutation becomes UNKNOWN; expired ownership without one may be reclaimed to resume persisted delays/polls, or perform a new final admission for the next step.
3. The transport enforces an adapter-declared maximum request budget per step. Reserve those units in the existing shared per-organization bucket before DB mutation admission, record them on the call, then meter every actual outbound sub-request. Empty/unavailable Redis means no admission. Polls reserve separately, use exponential backoff and a fixed deadline, and defer on budget exhaustion. No fixed60-per-hour polling allowance. Capability metadata states exact units. An attempted request beyond a reserved bound after any network mutation is UNKNOWN. Only the transport's own sent ledger may prove NOT_SENT; an adapter error cannot erase an earlier sub-request. Conservatively keep reserved unused units, consistent with the existing budget design.
4. A scheduling/publish HTTP acknowledgement is `accepted`, never published. W&W0124 must store durable lifecycle-operation and dispatch mirrors, their sequence cursor and retry timing. Only verified DISPATCH_PUBLISHED or RESOLVED_PUBLISHED evidence changes a delivery to published. Nonterminal/unresolved dispatches remain in the non-inert/hold predicates even after the HTTP operation completes. Add shared human-confirmed `post.cancel_schedule` with exact scope and `post.resolve_dispatch` with exact version/per-member decisions/evidence; a lookup alone cannot clear a provider UNKNOWN.
5. Freeze both W&W approved `contentSha256` and independently derived owned `releaseHash` in the action confirmation and SQL ledger, alongside revision/binding/schedule generations and the exact affected occurrence scope. Text/settings come from W&W's approved payload; media digest/size/type come from the retained W&W upload bindings. Owned opaque IDs may come from prior acknowledged bindings, never supply trusted text/media values from release-preview. Preview is a comparison, not the source of truth. Provider byte transforms require the corresponding reviewed bytes, never an unproved substitution.
6. Lifecycle events have a separate durable feed/cursor and bounded lookup endpoint. Legacy CREATE_DRAFT/EDIT_DRAFT operation replay remains unchanged; looking up a lifecycle key on the old operation endpoint returns a typed409 kind mismatch, never ABSENT. Root source inspection corrects part of the review: the current W&W v2 post/snapshot decoder already accepts DRAFT, QUEUE, PUBLISHED and ERROR; it does not accept DELETED or new event kinds. Do not fabricate DRAFT or ERROR to hide deletion. New lifecycle-qualified composition must use the new lifecycle/tombstone projection and stop treating its own authorized transitions as foreign writes. Preserve existing DRAFT behavior with lifecycle off. Add tests using the actual existing decoder for accepted states, and explicit fail-closed behavior for unsupported lifecycle/tombstone states; do not claim old clients are lifecycle-compatible. Never rewrite immutable revision snapshots or omit retained history to make a decoder pass. Inventory/feed integration must either preserve old sequence semantics or require the new qualified protocol explicitly; a cursor must not loop forever on an unconsumable event.
7. Publish-now refuses an active schedule. UI offers an explicit human-confirmed cancel first; there is no implicit cancel/re-publish shortcut.
8. Media capability materialization verifies the entire pinned object's digest, byte length, MIME and current scope; each fetch verifies against immutable retained bytes. Ranges are served only from that verified object. Capability lifetime is tied to one admitted call and its provider ingestion/pending completion, then revoked. Token/URL is excluded from approved-content and request hashes and from logs/recorders/evidence. `requiresMedia` is an explicit adapter fact; the actual `instagram-standalone` adapter cannot admit text-only content. Fake transport proves synthetic byte fetches and every invalid/expired/revoked/mismatched request is refused.
9. Immediately before each outgoing mutation, lock/check the exact call row: DISPATCHING, current holder, expected dispatch version and lease expiry at least now plus the adapter deadline. Settle compares the same holder/version. No lock is held over network IO. Recovery may not reclaim a live unexpired admission. A paused sender still makes exactly-once claims impossible; its durable UNKNOWN must prevent a second automatic send.
10. Freeze one final wire fixture set, shared by owned DTO and W&W decoder tests. Do not implement the app plan's obsolete PROPOSED unschedule/remove/v3 endpoints. The owned contract is ww.managed-lifecycle.v1 with schedule/publish-now/cancel/delete/resolve and dedicated lifecycle lookup/feed.

Dependent schema/runtime implementation must incorporate these corrections. Closed DTO work can be reconciled against this record before integration; no partially implemented DTO is live qualification.
