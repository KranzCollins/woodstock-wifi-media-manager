## Codec review reconciliation

The legacy v2 DRAFT storage contract accepts a broader text domain than safe publication. Preserve it unchanged. The new `MANAGED_PUBLICATION_TEXT_RULES` in `managed.publication-text.ts` declares the distinct `ww-managed-publication-text-v1` policy, all refused character classes, one-pass canonical decoding, the DTO character measure and the hard UTF-16 size bound. Lifecycle capabilities must expose that descriptor, and release preview/request acceptance must run the real decoder before queuing. Do not postpone these refusals until a scheduled send and do not claim a DRAFT acceptance implies publication qualification. Existing historical drafts remain readable. This resolves the independent codec review's policy mismatch without changing the old v2 pin or weakening the W&W text domain.

## Storage integration decisions

The additive schema contains eight models. Shared `ManagedOperation` claims use the lifecycle kind and sequence 0 only for new lifecycle operations; zero means no position in the legacy DRAFT feed. The old operation lookup and replay must return `OPERATION_KEY_KIND_MISMATCH` before any lifecycle writes can be activated. Existing claims and immutable snapshots are unchanged.

Logical lifecycle mutations use the existing managed organization lock first, then the separate lifecycle counter. Media fetch quota and revocation are deliberately single-statement conditional updates on one capability; they do not take the organization lock. They do not change a post, lifecycle operation, approval or feed. Revocation remains retained and the service rechecks the call before returning bytes. This exception keeps a provider's authorized media read from waiting on unrelated draft authoring. Unique `(organizationId, callId, mediaId)` is accepted in addition to the evidence uniqueness: one call cannot mix two byte revisions of the same media.

A stale sender's late result must not overwrite a newer dispatch version. Dispatcher integration must retain sanitized late evidence for human review without clearing UNKNOWN or automatically retrying; the current schema alone does not implement this behavior. No exact-once or continuous external-state guarantee is claimed.

## Cancellation contract reconciliation

Every cancel keeps the existing schedule generation and increments the schedule version. REMAINING may truncate from any still-future occurrence, leaving earlier pending, admitted and unmaterialized occurrences untouched. The exact affected list and any earlier admitted/unresolved dispatch are bound by the confirmation digest. ENDING series may be shortened again but never extended. This supersedes older storage/proposal wording that advanced the post generation or required fromOccurrence to be the first unsettled occurrence. A never-scheduled DRAFT is removable at generation0 through retained soft deletion; no social-network deletion is implied.

## Resolution and cleanup authorization reconciliation

- SCHEDULE/PUBLISH_NOW and every provider request require the current publication policy and original captured schedule window. CANCEL, retained DELETE and human RESOLVE perform no provider IO; they require explicit organization/scoped write authority and the exclusive test-access cutoff, but do not require an open publication window or running dispatcher. The W&W client retains explicit `qualified=true` for every write; revoking qualification revokes authority and is not the emergency dispatcher switch. All live qualifications remain absent. No new operation is accepted at or after 2026-11-10T23:00:00Z. Exact idempotent replays remain retained read-only answers.
- A mutation result UNKNOWN/PARTIAL halts automatic progression. A later human RESOLVED_PUBLISHED may resume only that same latest captured series when HALTED endedCode matches the unresolved dispatch, no later occurrence exists and no intervening human termination owns the halt. It never resends the resolved occurrence, extends lastOccurrence or renews the captured policy. Known failures and human NOT_PUBLISHED/ABANDONED halts do not resume.
- Pending media uses the original mutation call version even when polling changes dispatch ownership. Each fetch rechecks current authority; the immutable token has an independent maximum15-minute lifetime and is never reminted. Long provider ingestion may therefore fail closed and is not guaranteed.
- Runtime presence expires with the conservative30-second Redis lease bound. Mount the capability media controller only in the isolated runtime, which does not initialize Sentry or record URL access logs. Its output limit is process-wide.
